# Яндекс Метрика: реестр счётчика и событий Pitchy

## Принцип настройки

Для продукта используется один production-счётчик для `https://pitchy.pro`.
`dev.pitchy.pro`, localhost, сотрудники и тестовые аккаунты исключаются из отчётов фильтрами. Отдельный счётчик для dev не требуется: он создаёт шум и не отвечает на продуктовые вопросы.

События именуются латиницей в `snake_case`. В Метрике для каждого из них создаётся цель типа **«Целевое событие»** с тем же идентификатором.

Не передавать в Метрику: email, имя, текст чатов, описания стартапов, ссылки на документы, номера заказов и иные персональные или коммерчески чувствительные данные.

## Ключевые KPI

| Метрика | Определение | Зачем |
| --- | --- | --- |
| Activation rate | Пользователь завершил onboarding и создал первый проект / зарегистрировался | Понимать, превращается ли регистрация в использование продукта |
| Time to value | Время от регистрации до первого завершённого результата | Находить трение на первом сценарии |
| Feature adoption | Доля активных пользователей, которые успешно завершили сценарий конкретной функции | Сравнивать ценность чата, грантов, CustDev и дорожной карты |
| Checkout conversion | Успешная оплата / начало оплаты | Искать потери в оплате |
| Paid activation | Оплативший пользователь, использовавший хотя бы одну оплачиваемую функцию за 7 дней | Отделять выручку от реального удержания |

## Общая воронка и монетизация

| Приоритет | Идентификатор цели | Когда отправлять | Параметры без персональных данных |
| --- | --- | --- |
| P0 | `signup_success` | Backend успешно создал аккаунт | `auth_method` |
| P0 | `email_verified` | Email подтверждён | — |
| P0 | `onboarding_completed` | Пользователь завершил onboarding | — |
| P0 | `project_created` | Первый/очередной проект сохранён | `project_source` |
| P1 | `pricing_opened` | Открыта страница тарифов | `entry_point` |
| P0 | `checkout_started` | Backend создал платёж и вернул ссылку ЮKassa | `price_rub`, `has_promo`, `plan_type` |
| P0 | `payment_succeeded` | ЮKassa webhook подтвердил успешную оплату | `price_rub`, `plan_type`, `is_first_payment` |
| P1 | `promo_applied` | Промокод успешно применён | `discount_type` |
| P1 | `upgrade_prompt_shown` | Показано предложение повысить тариф | `feature`, `reason` (`locked`/`quota`) |
| P1 | `contact_form_sent` | Обращение успешно принято сервером | `subject` |

`payment_succeeded` — только серверное событие через Measurement Protocol: возвращение пользователя из ЮKassa не подтверждает оплату. Остальные клиентские события отправляются после успешного API-ответа, а не по клику.

## Гранты

| Приоритет | Идентификатор цели | Условие успеха | Полезные параметры |
| --- | --- | --- | --- |
| P1 | `grants_opened` | Открыт раздел грантов | `entry_point` |
| P1 | `grant_match_completed` | Подбор грантов для проекта успешно вернул результаты | `matches_bucket` (`0`, `1_5`, `6_plus`) |

| P1 | `grant_application_saved` | Пользователь сохранил/обновил заявку | `status` |

Главная метрика модуля: доля активных проектов с `grant_application_generated`; дополнительная — конверсия `grant_match_completed` → `grant_application_generated`.

## CustDev

| Приоритет | Идентификатор цели | Условие успеха | Полезные параметры |
| --- | --- | --- | --- |
| P1 | `custdev_opened` | Пользователь открыл CustDev из Pitchy | `entry_point` |
| P0 | `custdev_run_started` | Сервер принял запуск CustDev-исследования | `research_type` |
| P0 | `custdev_run_completed` | Исследование завершено, результат доступен | `research_type` |
| P1 | `custdev_report_opened` | Открыт готовый отчёт | — |
| P2 | `custdev_report_exported` | Отчёт экспортирован | `format` |
| P1 | `custdev_limit_reached` | Функция недоступна из-за тарифа/лимита | `reason` |

CustDev расположен на `custdev.pitchy.pro`. Чтобы сессии не распались на два сайта, используем тот же ID счётчика и включаем кросс-доменное отслеживание для `pitchy.pro` и `custdev.pitchy.pro`.

## Динамический трек (дорожная карта)

| Приоритет | Идентификатор цели | Условие успеха | Полезные параметры |
| --- | --- | --- | --- |
| P1 | `roadmap_opened` | Открыта дорожная карта проекта | `entry_point` |
| P0 | `roadmap_created` | Дорожная карта с checkpoint'ами успешно создана | `source` |
| P0 | `roadmap_checkpoint_completed` | Пользователь отметил checkpoint выполненным | `checkpoint_type` |
| P1 | `roadmap_step_analysis_completed` | Получен анализ отдельного шага | `checkpoint_type` |
| P1 | `roadmap_overall_analysis_completed` | Получен общий ИИ-анализ трека | — |
| P2 | `roadmap_exported` | Скачан PDF дорожной карты | `format` (`pdf`) |
| P1 | `roadmap_limit_reached` | Функция заблокирована тарифом/лимитом | `reason` |

Для трека важнее всего retention: доля проектов, у которых есть `roadmap_checkpoint_completed` на 7-й и 30-й день после `roadmap_created`.

## Порядок внедрения

1. Подключить один счётчик на `pitchy.pro`; настроить CSP и исключения тестового трафика.
2. Реализовать P0-события общей воронки, чата, CustDev и дорожной карты.
3. Включить Measurement Protocol и передавать успешные платежи с backend после webhook ЮKassa.
4. Подключить тот же счётчик к `custdev.pitchy.pro` с кросс-доменной связкой.
5. Добавить P1/P2-события и собрать отчёты по воронкам функций.

## Статус реализации

В frontend подключён счётчик `111275219`, SPA-hit при клиентской навигации и P0/P1-события для регистрации, подтверждения email, onboarding, создания проекта/чата, старта оплаты, контактной формы, подбора грантов и ключевых действий дорожной карты. В CSP Caddy и Next.js разрешён `https://mc.yandex.ru`.

Для `payment_succeeded` и серверных завершений CustDev нужен следующий ручной шаг: включить Measurement Protocol в настройках счётчика и безопасно передать токен в backend через переменную окружения. Токен нельзя помещать в frontend или репозиторий. После этого backend должен передавать подтверждённые webhook ЮKassa оплаты, а сервис `custdev.pitchy.pro` — фактические успешные запуски и отчёты.
