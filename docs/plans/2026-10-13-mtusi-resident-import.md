# Импорт действующих участников МТУСИ 2026

Источник: приватный снимок выгрузки, переданной организатором. Исходные ответы, ники и пароли не включаются в публичный репозиторий.

Решения пользователя: непосредственное зачисление (enrolled), общие проекты команд, одинаковый шаблон категорий, пустой «Будущий проект» для участников без идеи, отдельные паспорта самостоятельных идей. Пароли новых аккаунтов: 16 ASCII-символов с прописными/строчными латинскими буквами, цифрами и спецсимволами. Существующие пароли сохраняются.

## Этапы

1. Зафиксировать приватный снимок источника; нормализовать контакты; выявить повторы, противоречия и группы проектов. Не выбирать конфликтующие ответы без решения пользователя.
2. Реализовать локальный логин с обратной совместимостью входа по email. Допуск импортированного аккаунта к входу хранить отдельно от подтверждения почты.
3. Реализовать проверяемый манифест импорта: участники, общие/личные проекты, капитаны, основные проекты, структурированные поля и связь с исходными ответами. До записи проверять весь пакет и совпадения с базой.
4. Реализовать непосредственное зачисление без искусственных заявок, назначение лимитов потока и аудит. Одна атомарная транзакция, повторный запуск без изменения паролей, паспортов, составов и статусов.
5. Обеспечить командный доступ к общему паспорту и разбивке. Владелец управляет проектом; активные члены команды совместно редактируют содержание. Сотрудники читают проект только в своём разрешённом контексте.
6. Показывать описание, проблему, решение и аудиторию в карточке резидента; у участника показывать описание и переход к паспорту. Для всех проектов использовать один шаблон разбивки.
7. Подготовить и вручную сверить каждый паспорт с исходником: сохранить каждое существенное утверждение, неизвестные сведения оставить пустыми, планы отличать от реализованных функций. Дополнительные сведения сохранять в читаемом поле.
8. Выполнить автоматические проверки, тестовый импорт, проверку через интерфейс. Рабочий импорт требует точных ID среды/потока и разрешённых конфликтов, предварительной резервной копии и сверки результата.

## Обязательные проверки

- Нормализация ников, корректность email, уникальность учётных записей, конфликт email/логина, заблокированные и удалённые пользователи.
- Длина/алфавит/состав/уникальность паролей, хеширование, отсутствие секретов в отчёте и Git, сохранение существующих паролей.
- Вход по email и логину (регистр, @), одинаковая блокировка попыток, неподтверждённая почта обычных аккаунтов, импортированный допуск к входу.
- Миграция вперёд/назад, отсутствие заявок при прямом импорте, enrolled, квоты, журнал зачисления, отсутствие уведомлений без отдельного поручения.
- Весь пакет проверяется до изменений; dry-run не изменяет базу; сбой откатывает пакет; повторный запуск не меняет пользовательские данные; изменённый пакет с тем же ID отвергается.
- Один проект/паспорт/дерево на общую идею; несколько самостоятельных идей не смешиваются; основной проект указан явно.
- Одинаковые категории и порядок во всех деревьях, пустые поля не повышают готовность, текст не обрезается, ссылка паспорт–разбивка проверяется.
- Капитан и каждый активный член команды видят и редактируют общее содержание; чужой участник, исключённый член, приостановленный участник не получают доступ; удаление/архивация ограничены владельцем.
- Описание в акселераторе совпадает с паспортом, права организатора и трекера проверяются, списки участников содержат импортированных резидентов.
- Проверка каждого подготовленного паспорта по исходным ответам и итоговая сверка числа аккаунтов, проектов, команд, членств и лимитов.

## Открытые данные

Решения получены: отдельные аккаунты по никам без привязки к почте; противоречивую стадию исправляем согласно указанию организатора; первые участники групп становятся временными капитанами; основные проекты выбираются по указанию организатора и могут быть изменены пользователем. Рабочий перенос выполняется через Git и CI после проверок. Точный ID потока и его лимиты подтверждаются предварительным чтением рабочей базы.
