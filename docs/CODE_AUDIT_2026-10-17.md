## Подтверждённые кандидаты на чистку

### 1. Пять недостижимых обработчиков авторизации в `main.py` — высокий приоритет

`main.py` подключает `routers/auth.py` до объявления собственных обработчиков. Оба модуля регистрируют одинаковые POST-пути:

| Путь | Старый обработчик в `main.py` | Активный обработчик в `routers/auth.py` |
| --- | --- | --- |
| `/auth/change-password/initiate` | около строки 1788 | около строки 508 |
| `/auth/change-password/confirm` | около строки 1820 | около строки 552 |
| `/auth/resend-verification` | около строки 1851 | около строки 398 |
| `/auth/request-password-reset` | около строки 1880 | около строки 583 |
| `/auth/reset-password` | около строки 1918 | около строки 617 |

FastAPI/Starlette сопоставляет запрос с первым зарегистрированным маршрутом, поэтому варианты из `main.py` фактически затенены. Это также создаёт неоднозначность в OpenAPI: описание пути может не соответствовать функции, которая отвечает на запрос. Маршрутизатор уже содержит комментарий о другом историческом конфликте `/auth/verify-email`; для перечисленных пяти путей дубли подтверждены по текущим декораторам.

**Действие:** зафиксировать тестами фактический обработчик, код ответа и схему каждого пути. После этого удалить затенённые функции и неиспользуемые импорты из `main.py`, сравнив сценарии отправки писем, лимиты запросов и журналирование.

### 2. `makura_client.py` — не используется рабочим кодом

В рабочем Python-коде нет импортов `makura_client.py` и вызовов `call_makura`/`stream_makura`. Упоминание `stream_makura` обнаружено только в `scratch/patch_orchestrator.py`; [документ об ИИ-конвейере](AI_PIPELINE_ARCHITECTURE.md) уже называет модуль устаревшей обёрткой. Актуальный провайдер генерации — `polza_client.py`.

**Действие:** после проверки внешних скриптов перенести обёртку в архив или удалить и убрать ссылку на неё из эксплуатационных инструкций. Миграции и исторические примеры не считать потребителями production.

### 3. Старые входы чата — кандидаты на вывод из эксплуатации

`POST /chat` и `POST /chat/messages` в `main.py` помечены `deprecated=True, include_in_schema=False`. Текущий клиент в `frontend/lib/api.ts` отправляет сообщения через `/chat/sessions/{sessionId}/messages`. Это подтверждает отсутствие вызова старых путей из текущего интерфейса, но не доказывает отсутствие внешних клиентов.

**Действие:** проверить логи запросов и интеграции, объявить срок прекращения поддержки, затем удалить старые пути вместе с относящимися к ним преобразованиями. До проверки логов их следует считать поддерживаемым API.

### 4. `lovable/` и `scratch/` — вне основной сборки

Основной frontend собирается из `frontend/`, backend — из корня. Конфигурации Docker/Compose и workflow не запускают `lovable/` и `scratch/`. `lovable/` выглядит как отдельный прототип, а `scratch/` содержит разовые эксперименты. Это кандидаты на перенос в архивный репозиторий или документацию, а не подтверждённо «мёртвые» функции.

**Действие:** выяснить владельца и назначение каталогов, затем либо явно описать их поддержку, либо вывести из основного репозитория.

### Отдельная конфигурационная особенность

`Dockerfile` содержит команду запуска с `alembic upgrade head`, но `docker-compose.yml` переопределяет команду backend на прямой `uvicorn`. При штатном деплое `deploy.sh` отдельно применяет и проверяет миграции. Изменение пути запуска контейнера без этого скрипта может пропустить миграции. Это не означает, что текущий production-деплой сломан; важно сохранить единую гарантированную точку применения миграций.
