# Pitchy

Pitchy — веб-платформа для развития стартап-проекта: анализ идеи и чат с ИИ, паспорт и дорожная карта проекта, исследования, гранты и программы акселерации. Этот репозиторий содержит сайт, API, модели данных, миграции, тесты и инфраструктуру. Описание сверено с веткой `main` на 14 октября 2026 года (`942d053`).

## Возможности

| Модуль | Для чего нужен | Реализация |
| --- | --- | --- |
| Аккаунт | Регистрация, подтверждение почты, вход, сброс и смена пароля, SSO, профиль | `routers/auth.py`, `auth.py`, `main.py` |
| Анализ и чат | Оценка идеи, сессии, потоковые ответы, вложения, обратная связь, экспорт | `main.py`, `chat_pipeline.py`, `chat_attachments.py`, `export_service.py` |
| Знания и поиск | RAG по документам и проекту, Chroma, ранжирование, внешний поиск | `rag.py`, `rag_reranker.py`, `search_agent.py` |
| Исследование | План, сбор источников, извлечение и проверка фактов, отчёт | `research_service.py`, `routers/research.py` |

| Акселератор | Наборы, заявки, резиденты, команды, трекеры, программа, задания, события, прогресс, уведомления, выпускники | `routers/accelerators.py`, `routers/accelerator_*.py`, `accelerator_*_service.py` |
| Аудитория | Кампании, персоны, интервью, демонстрационные сценарии и отчёты | `routers/audience_simulations.py`, `audience_simulation_service.py` |
| Монетизация | Подписки, платежи, промокоды, квоты, продления | `billing.py`, `subscription_service.py`, `promo_service.py` |

Функции доступны в зависимости от роли, настроенных внешних сервисов и включённых модулей программы.

## Архитектура и поток данных

```text
Браузер → Next.js 16 / React 19 (frontend/)
        → FastAPI (main.py + routers/)
          ├─ PostgreSQL / SQLAlchemy / Alembic: основные данные
          ├─ Redis: ограничения запросов, состояние и кэш
          ├─ Chroma: векторный поиск
          ├─ Polza: генерация, классификация и эмбеддинги
          ├─ Exa: интернет-поиск
          ├─ RouterAI: rerank API
          └─ SMTP / платёжные провайдеры: письма и платежи
```

`main.py` создаёт приложение и подключает маршрутизаторы. Модели находятся в `models.py`, схема обновляется миграциями из `alembic/versions/`. Синхронное и асинхронное подключения описаны в `db.py` и `db_async.py`. Пользовательские страницы расположены в `frontend/app/`, компоненты — в `frontend/components/`, вызовы API — в `frontend/lib/api.ts`. `frontend/next.config.ts` проксирует часть запросов к backend.

**Запрос чата:** интерфейс открывает сессию и отправляет сообщение в `/chat/sessions/{session_id}/messages`. API проверяет доступ и лимиты, разбирает вложения и контекст проекта. Маршрутизация выбирает локальные знания и необходимость актуального поиска. `chat_pipeline.py` собирает историю и найденные источники; для некоторых аналитических запросов подключается `swarm_agent.py`. Ответ передаётся через SSE и сохраняется. Границы провайдеров подробно описаны в [архитектуре ИИ-конвейера](docs/AI_PIPELINE_ARCHITECTURE.md), исследовательский сценарий — в [обзоре глубоких исследований](DEEP_RESEARCH_OVERVIEW.md).

**Данные и роли:** основные сущности — пользователи, проекты и паспорта, анализы, сессии и сообщения, результаты инструментов, исследовательские задания и источники, гранты и заявки, подписки и платежи, акселераторы, потоки, участники, команды и задания. Поля и связи смотрите в `models.py`. Есть публичные и гостевые сценарии, а также права пользователя, администратора, организатора, трекера и резидента. Проверки доступа расположены в зависимостях FastAPI и сервисах модулей.

### Основные пользовательские сценарии

**От идеи к проекту.** Пользователь может начать с разового анализа или создать проект. Паспорт сохраняет сведения о продукте и команде, дерево проекта разбивает работу на узлы, а дорожная карта показывает этапы и контрольные точки. В backend этим занимаются `projects_router.py`, `passport.py`, `tree_router.py` и `roadmap_service.py`. Дорожную карту можно анализировать и экспортировать. Изменение полей паспорта учитывается при пересчёте зависимых выводов.

**Диалог и знания.** Чат поддерживает отдельные сессии, историю, загрузку файлов, источники, обратную связь и экспорт. Запрос может идти по локальной базе знаний, по внешнему поиску или через несколько этапов анализа. `rag.py` управляет индексом и извлечением; `search_agent.py` отвечает за внешние источники; `chat_pipeline.py` формирует контекст модели. Данные проекта включаются с учётом доступа пользователя.

**Глубокое исследование.** Запрос создаёт исследовательское задание. Сервис формирует план, ищет источники, ранжирует документы, извлекает утверждения, проверяет их и пишет итоговый отчёт. В базе сохраняются задание, источники, утверждения и подтверждения, чтобы результат можно было показывать с основаниями. Подробнее о стадиях и ограничениях — в `DEEP_RESEARCH_OVERVIEW.md`.

**Гранты.** Каталог можно просматривать и фильтровать; для проекта доступно сопоставление условий гранта с паспортом. Административные операции управляют источниками и модерацией. Пользователь может вести заявку и получать материалы, созданные на основе данных проекта. Уточняйте фактические критерии конкретного гранта у его организатора: автоматически извлечённые сведения могут устареть.

**Программа акселерации.** Организатор настраивает акселератор, поток и модули программы, публикует материалы и задания, отслеживает события и прогресс. Участник подаёт заявку и после вступления работает в кабинете резидента. Отдельные сервисы отвечают за команды, трекеров, уведомления, артефакты, аудит проекта, выпускников и ограничения доступа. Разделение прав зависит от статуса потока и роли в программе; подробная матрица находится в [документе о ролях](docs/accelerator-role-matrix.md).

**Моделирование аудитории.** Администратор или оператор создаёт кампанию и запуск. Система формирует и опрашивает персоны, агрегирует результаты и создаёт отчёт; отдельный режим использует преднастроенные демонстрационные сценарии. Для выдачи результатов участникам предусмотрены ссылки и QR-коды. Такие результаты являются моделированием, а не прямыми ответами реальных клиентов.

## Запуск разработки

Нужен Docker с Compose. Для ручного запуска используются Python 3.11 и Node.js 20 (версии Dockerfile), PostgreSQL, Redis и Chroma.

1. Скопируйте `.env.production.example` в `.env` и задайте локальные адреса и секреты. Как минимум установите `APP_ENV=dev`, `DATABASE_URL=postgresql+psycopg2://postgres:postgres@postgres:5432/app`, `APP_PUBLIC_URL=http://localhost:3000`, `FRONTEND_ORIGINS=http://localhost:3000` и случайный `APP_SECRET_KEY`. Значение `DATABASE_URL` из production-примера не подходит к учётным данным dev Compose. Для ИИ, почты и оплаты понадобятся тестовые ключи соответствующих сервисов. Секреты не коммитьте.
2. Запустите окружение:

   ```bash
   docker compose -f docker-compose.dev.yml up --build
   ```

3. Примените миграции:

   ```bash
   docker compose -f docker-compose.dev.yml exec backend python -m alembic upgrade head
   ```

4. Интерфейс: `http://localhost:3000`; документация API: `http://localhost:8000/docs`; проверка готовности: `http://localhost:8000/ready`.

В dev Compose исходники примонтированы в контейнер. Для ручного запуска установите `requirements.txt` и запустите `uvicorn main:app --reload` с настроенными хранилищами. В папке `frontend/` выполните `npm ci --legacy-peer-deps` и `npm run dev`. Полноценная работа функций с внешними API требует доступности этих сервисов.

## API и проверки

Текущий контракт FastAPI доступен в `/docs` и `/openapi.json`. Основные группы: `/auth/*` и `/me*`, `/chat/*` и `/analysis`, `/projects/*` и `/tree/*`, `/grants/*`, `/billing/*`, `/api/tools/*`, `/api/rag/*`, `/api/research/*`, `/api/accelerators/*` и `/admin/*`. Состояние сервиса: `/live`, `/ready`, `/health`, `/metrics`. Старые chat-маршруты помечены `deprecated` и скрыты из схемы.

```bash
python -m pytest tests
npm run lint --prefix frontend
npm run build --prefix frontend
```

Браузерные сценарии: `npm run test:e2e --prefix frontend` после настройки Playwright и окружения. Тестам с внешними сервисами нужны тестовые ключи либо заглушки. GitHub Actions содержит сборку, тестовый Docker-target, деплой и отдельную проверку безопасности; полный локальный набор проверок шире обязательного CI-gate.

## Развёртывание и состояние кода

Production-стек использует PostgreSQL, Redis, Chroma, backend, frontend и Caddy. Порядок деплоя и отката описан в [DEPLOY.md](DEPLOY.md) и `deploy.sh`, резервные копии — в `ops/backup/`. Изменения схемы проводите через Alembic. Обратите внимание: штатная команда backend-образа запускает миграции, но Compose переопределяет команду контейнера; реальный сценарий нужно сверять с deploy-скриптом.

[Аудит неиспользуемого кода и оптимизаций](docs/CODE_AUDIT_2026-10-17.md) содержит подтверждённые и вероятные находки, ограничения статического анализа и рекомендуемый порядок работ.
