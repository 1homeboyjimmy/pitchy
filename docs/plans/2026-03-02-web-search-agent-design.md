# Web-Search Agent Design (Hybrid RAG)
Дата: 2026-03-02

## Цель (Goal)
Вместо классического дообучения весов LLM (Fine-Tuning), мы развиваем RAG (Retrieval-Augmented Generation), внедряя **Agentic Web-Search**. Это позволит ИИ-Copilot'у не только опираться на наши 4000+ оффлайн-чанков, но и программно принимать решения о поиске актуальных цифр в интернете (объемы рынка, цены, конкуренты, гранты).

## Архитектура: LLM-Router + Web-Search (Синхронный агент)

Процесс обработки запроса разделяется на две стадии:

### 1. Этап Маршрутизации (The Router)
Когда поступает запрос пользователя (в `main.py` -> `/chat/sessions/{session_id}/messages`):
*   Сначала отправляем легкий запрос (например, базовый или дешевый YandexGPT Lite) с жестким системным промптом классификатора.
*   **Задача Роутера:** проанализировать вопрос пользователя и решить, требуются ли ему актуальные данные из интернета (например, упоминается текущий год, специфика конкретного узкого рынка, поиск конкурентов по имени).
*   **Ответ Роутера (JSON):** `{"needs_search": true, "search_query": "Объем рынка кофеен в Москве 2026"}` или `{"needs_search": false, "search_query": null}`.

### 2. Этап Исполнения (The Execution)
*   **Если `needs_search == false`**:
    *   Запрос идет по стандартному сценарию: ищем 3 релевантных куска в ChromaDB -> отдаем в основную LLM вместе с историей диалога -> стримим ответ пользователю.
*   **Если `needs_search == true`**:
    *   Бэкенд берет `search_query` и делает запрос к поисковому API (например, Yandex Search API или DuckDuckGo / Tavily).
    *   Мы берем первые 2-4 ссылки, пропускаем их через наш `scraper.py` (чистим HTML, оставляем только текст).
    *   Создаем новый синтетический контекст (смешиваем найденные в интернете тексты + релевантные куски из нашего оффлайн RAG).
    *   Отдаем этот комбинированный контекст в основную LLM.
    *   Стримим ответ пользователю.

## Технические компоненты

1.  **Search Module:** Функция (например, в `rag.py` или новом `search_agent.py`), которая принимает строку, делает поисковый запрос, парсит страницы и возвращает markdown-строку с фактами.
2.  **LLM Router Module:** Функция, вызывающая легковесную модель с JSON-схемой `{"needs_search": bool, "search_query": str}`.
3.  **Интеграция в пайплайн чата:** Модификация эндпоинта отправки сообщений в `main.py`.

## Отказоустойчивость и Ограничения
*   **Тайм-ауты парсинга:** Если сайт не отдается за 3 секунды, пропускаем его. Мы не должны заставлять пользователя ждать больше 10-15 секунд до начала генерации текста.
*   **Fallback:** Если поиск упал или не дал результатов, ИИ прозрачно сообщает об этом и отвечает на основе RAG-базы.
